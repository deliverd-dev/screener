        How Screener works
        
        
          
          
        1. It looks, in your browser. As you type, Deliverd Screen looks for email addresses, phone numbers, card numbers, IBANs, national ID numbers, keys, passwords, special-category words such as a diagnosis, and your own confidential words. It runs in this tab, with no network call.
          2. 
          
        2. It decides again when you press Send. Run it yourself and the little server that comes with it checks the same text again; it never takes the page's word for it. In the hosted demo there's no server, so the same check runs in your tab.
          3. 
          
        3. Four answers. Allow sends it as it is. Redact swaps what the model may not receive for placeholders such as [EMAIL_1], and puts the real values back in the answer. Ask puts it to a person first. Deny sends nothing: secrets never go.
          4. 
          
        4. A person decides the hard ones. In the playground, that's you, at the approver's phone on this page. Connect Deliverd and it's the people you name, in Slack, Teams or on their phone, with a record of who said yes. They're told what kind of data it is, never the data.
          5. 
          
        5. Agents ask too. The page is built with Vercel UI SDK, so an agent can use it. The model settings carry a data-agent-confirm mark, so an agent that tries to loosen them waits for a person. A browser's own agent can use the page through WebMCP, under the same rule.
          6. 
        
        
        
        A net, not a certificate. Structured identifiers are found well; names are not found at all without a model. Text with placeholders in it can still be personal data. Use it to send less, never as proof a prompt was clean.
